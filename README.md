# 智绘适老

“智绘适老”是面向家庭适老化改造场景的移动端网页前端。产品围绕空间采集、人因风险判断、改造方案匹配和改造后反馈建立完整流程，并提供可直接浏览的方案商城与效果社区。

- 在线地址：<https://batch-li.github.io/web-demo/>
- GitHub 仓库：<https://github.com/Batch-Li/web-demo>
- 默认分支：`main`
- 部署方式：GitHub Actions + GitHub Pages

当前仓库可在没有后端服务的情况下完整运行。页面状态保存在浏览器本地，图片均随项目发布，不依赖临时外链。

## 产品目标

项目以“识别判断 → 方案转化 → 效果验证”为主链路，解决三个连续问题：

1. 如何结合老人个体情况与住宅空间证据识别风险。
2. 如何把风险结论转换为具体改造动作、产品或服务及执行条件。
3. 如何通过改造后复扫、人因任务评价和社区反馈验证实际效果。

产品底部保留三个一级入口：

| 入口 | 主要能力 | 核心输出 |
| --- | --- | --- |
| 扫描 | 用户画像、空间选择、分视角采集、智能分析、结果复核 | 安全分、风险等级、可解释原因、改造方向 |
| 方案 | 分类浏览、搜索筛选、报告匹配、加入方案、预算汇总 | 产品与服务候选、适用条件、方案清单 |
| 效果社区 | 案例信息流、改造前后对比、复扫记录、发帖互动 | 效果反馈、人因任务体验、案例沉淀 |

## 核心流程

### 1. 扫描评估

扫描流程由七个连续页面组成：

```text
老人情况确认
  → 空间选择
  → 四个关键视角采集
  → 统一智能分析
  → 评估报告或复核任务
  → 方案匹配
  → 方案预览与复扫路径
```

评估同时考虑两类信息：

- 个体侧：年龄、行动方式、视物情况、平衡能力、跌倒经历、夜间活动和空间使用频率。
- 空间侧：湿滑、门槛、通道、照明、支撑设施、取物动线等采集证据。

用户主动确认的信息不会被描述为传感器实测数据。分析页在全部视角采集完成后启动，并按连续进度展示识别、校核和结果生成状态。

### 2. 结果与复核

结果页根据证据状态分流：

- 信息完整且满足发布条件：展示当前安全分、风险等级、风险原因和方案入口。
- 证据缺失或数据冲突：不生成正式数值，提供视频复核和上门复核入口。
- 完成复核：展示复核状态、当前安全分、方案执行后的预估区间及后续复扫要求。
- 未登记空间：进入普通复核队列，不自动映射为其他空间，也不生成正式风险结果。

所有改造后数值均属于方案执行前的预估提示。最终效果需要在同一空间、同一路径下重新采集确认。

### 3. 方案匹配

匹配逻辑不是普通商品推荐，页面按以下关系组织信息：

```text
风险诊断
  → 改造动作
  → 产品或服务类别
  → 尺寸、安装、预算与复核条件
  → 可执行方案清单
```

每个方案项展示：

- 对应风险与改造目标；
- 产品或服务名称；
- 适用空间和关键规格；
- 预算范围；
- 安装条件与现场确认要求；
- 加入或移出方案的操作。

任何必要安装条件为未知时，该候选不会作为可直接执行的推荐项，只生成待确认任务。

### 4. 方案商城

商城采用移动端材料设备库布局，包含：

- 搜索框；
- 报告匹配、施工方式和预算筛选；
- 左侧品类导航；
- 右侧连续商品列表；
- 收藏与加入方案操作；
- 已选方案数量和预算汇总；
- 分批展开商品列表。

商城数据与评估匹配共用同一商品目录，避免出现匹配页和商城名称、图片、规格不一致的问题。

### 5. 效果社区

效果社区采用真实信息流结构，支持：

- 改造案例与前后对比；
- 改造后复扫状态；
- 安全分前后对比；
- 起身、行走、转身、取物、通过门槛或通道、使用扶手等任务反馈；
- 点赞、评论、收藏；
- 本地发帖与图片选择；
- 话题和空间筛选。

社区闭环按以下顺序组织：

```text
改造前评估
  → 方案执行
  → 改造后复扫
  → 人因任务评价
  → 前后效果对比
  → 案例沉淀与规则校准
```

## 分数与规则口径

### 用户显示

- 用户页面展示“安全分”，数值越高表示当前空间越安全。
- 风险等级仍使用“低风险 / 中风险 / 高风险”，不会改写为“安全等级”。
- 报告、匹配摘要、方案预览和复扫案例使用同一显示口径。
- 待复核结果不显示虚构分数。

### 内部边界

- P1 内部仍使用风险值，数值越高表示风险越高。
- 安全分由独立只读显示层派生，不写回内部风险结果，也不传入 P2 路由。
- P2 只读取满足发布、结果类型、追溯完整性和复核状态要求的内部风险结果。
- 方案总分草案当前不参与计算；商品数量或方案覆盖情况不能替代安全分。
- 预算只绑定明确的前端样例条件，并显示“模拟估价 / 非报价”；真实费用需要现场确认。

## 页面状态与本地数据

应用使用 `localStorage` 保存当前体验进度，存储键为：

```text
zhihui-aging-demo:v7
```

持久化内容包括：

- 当前一级入口和扫描步骤；
- 已选择空间；
- 已完成采集任务；
- 老人情况；
- 已选方案项及确认状态；
- 当前浏览器新增的社区帖子。

读取本地数据时会执行白名单和范围校验，失效空间、商品、采集任务和超出流程范围的步骤不会直接恢复到页面。

需要从初始状态重新体验时，可在空间页使用“重新开始评估”，或清除该站点的浏览器本地存储。

## 图片素材管理

所有生产图片都位于 `public/assets/`，页面不会直接加载外部站点图片。这样可以避免防盗链、跨域、源站失效和网络波动导致的空白图。

新增或替换图片必须同时满足：

1. 图片内容与空间、商品名称、帖子正文和无障碍改造动作一致。
2. 主体清晰，不使用明显模糊、压缩破损、遮挡严重或带无关水印的图片。
3. 社区前后对比必须为同一空间，不能用两处不同住宅替代。
4. 商品图必须能直接识别商品主体，不能用泛家居场景代替。
5. 新文件放入对应目录，并同步更新 `src/demoData.js`。
6. 在 `public/assets/IMAGE_SOURCES.md` 记录来源和页面用途。
7. 运行测试，确认路径存在、语义字段完整且没有二进制重复。

图片来源、用途和维护要求详见 [public/assets/IMAGE_SOURCES.md](public/assets/IMAGE_SOURCES.md)。

## 响应式与设备展示

- `> 600px`：显示完整手机机身、金属外圈、侧键、状态栏、灵动岛和 Home 指示条。
- `<= 600px`：隐藏展示机身，页面以真实移动端全屏方式运行。

建议验收视口：

| 宽度 | 重点 |
| --- | --- |
| 375px | 小屏按钮、文字换行、底部导航、无横向溢出 |
| 393px | iPhone 基准内容宽度和完整业务流程 |
| 768px | 平板居中展示、手机外壳缩放和背景分离 |

录屏需要保留手机边框时，建议使用桌面视口并只裁取设备外壳区域；不要把浏览器页面背景一并录入。

`src/logic.test.js` 覆盖以下关键行为：

- 风险结果发布门控和待复核分流；

- 安装约束缺失、未知或失败时停止候选推荐；
- 预算来源与特定条件绑定；

## GitHub Pages 部署

`.github/workflows/deploy-pages.yml` 在每次推送到 `main` 后自动执行：

1. 检出代码；

4. 执行全部测试；
5. 以 `/web-demo/` 为基础路径生成生产构建；
6. 上传 `dist/`；
7. 发布到 GitHub Pages。

部署工作流：<https://github.com/Batch-Li/web-demo/actions/workflows/deploy-pages.yml>

线上地址保持不变：

```text

```

用于展示的二维码应始终编码该固定地址。后续更新 `main` 后，GitHub Pages 会在相同地址发布新版本，二维码无需重新生成。

## 修改指南

### 修改页面或交互

1. 在 `src/App.jsx` 调整结构和状态流转。
2. 在 `src/styles.css` 同步桌面手机展示与移动端样式。
3. 检查底部导航、页面滚动和返回路径。
4. 在 375、393、768、1280 四个宽度验收。
5. 检查控制台无 error 或 warn。

### 修改商品、空间或社区内容

1. 修改 `src/demoData.js`。
2. 将图片放入 `public/assets/` 对应目录。
3. 核对图片与标题、正文、规格和使用场景。
4. 更新 `public/assets/IMAGE_SOURCES.md`。
5. 运行测试和生产构建。

### 修改风险或方案规则

1. 先确认当前冻结基线和接口边界。
2. 在 `src/patentModel.js` 修改模型逻辑。
3. 保持内部风险结果、用户安全显示和 P2 方案路由相互隔离。
4. 为正常、缺失、冲突、越界和篡改场景添加反例测试。
5. 不在用户页面展示内部参数、哈希、规则编号或数据结构名称。

## 生产接入边界

当前仓库是完整前端实现，但以下能力需要后端或第三方服务后才能用于真实业务：

- 账号、家庭成员和权限管理；
- 图片上传、对象存储与内容审核；
- 真实图像识别与证据结构化；
- 风险结果签发和追溯记录服务；
- 人工复核工单、视频服务与上门排期；
- 商品库存、实时报价、订单和支付；
- 施工履约、验收和售后；
- 社区内容持久化、举报和审核；
- 真实复扫数据与规则校准后台。

接入后端时，应保留当前前端分流原则：证据不足不默认低风险，必要条件未知不直接推荐，待复核结果不生成正式数值。

## 隐私与安全

- 当前老人情况和用户发帖只保存在当前浏览器，不会上传到服务器。
- 不应在公开演示设备中输入真实姓名、联系方式、住址、病历或可识别个人身份的信息。
- 本地图片发帖使用浏览器数据 URL，仅用于当前浏览器展示。
- 清除站点数据会删除本地评估进度和本地新增帖子。

## 常见问题

### 直接打开 `index.html` 为什么无法使用？

项目使用 Vite 和 ES Modules，需要通过开发服务器或生产服务器访问，不能直接双击 `index.html`。

```bash
npm ci
npm run dev
```

### 端口 5173 被占用怎么办？

Vite 会自动选择可用端口，实际地址以终端输出为准。也可以指定端口：

```bash
npm run dev -- --port 5174
```

### 页面仍显示旧内容怎么办？

1. 确认 GitHub Pages 工作流已完成。
2. 强制刷新浏览器缓存。
3. 清除站点本地存储，避免旧流程状态被恢复。
4. 确认访问的是固定 Pages 地址，而不是旧的临时链接。

### GitHub Pages 图片路径错误怎么办？

应用通过 `resolvePublicAssetUrl` 处理 `/web-demo/` 基础路径。新增图片应使用 `/assets/...` 数据路径，不要在业务数据中硬编码仓库名称。

### 为什么有些空间要求复核？

当必要证据缺失、测量冲突、安装条件未知或空间未登记时，系统会停止生成正式结果，并引导用户提交视频或上门复核。该行为是产品流程的一部分，不是页面故障。
